# 实施计划

1. 用 `docs/design.md` 固定产品范围和上下文规则。客户端和宿主通过 `/api/dsh-btw-explore` 交换数据，所有请求均以当前会话 ID 为作用域。
2. 搭建原生「探索」视图、消息与选区入口。实现层级卡片、预览、问答详情、来源、停止和错误状态，打包为宿主支持的 Web 模块。
3. 用 `node:test` 对上下文边界、停止、恢复、会话隔离与模板事件做回归。实现 SQLite 数据、生成任务和 HTTP 桥接。数据库事务保持树关系、最新轮状态和任务所有权一致。
4. 在独立 DSH home 启动已安装版本，通过本地测试模型验证安装、问答、原会话事件、树与重启恢复。核对实际浏览器交互和窄布局。
5. 构建并检查 npm 包，记录安装和验证限制，清理临时进度文件。
